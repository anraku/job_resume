### AIサービスと連携するプロダクトの開発経験

現場作業の効率化を目的とした動画の解析をGeminiと連携して行うプロダクトの開発に従事していました。
このプロダクトの動画解析処理の基盤となる部分の開発に携わることにより、新しい知見を得ることができました。
主に動画解析のための前処理や、再生時間の長い動画の解析においていかにしてAIのハルシネーションを抑えるか等について考えることが多かったです。

### ストリーミング動画を扱うプロダクトの開発経験

上記の動画解析処理に伴い、動画の前処理やMP4からHLS形式のストリーミング動画への変換処理を実装しました。
動画の変換処理はRustで実装し、Knative JobSinkの仕組みを使ってAWS EKS上で動作する仕組みにしました。
大変だったのは動画の解像度をある程度担保しつつ現実的な時間でストリーミング動画に変換し、問題なくブラウザで再生されるよう検証することでした。
やることはffmpegのオプションを最適化するだけなのですが、変換する度にブラウザで再生できるかどうかを検証する必要があり時間のかかる作業でした。
それでも手元で色々と検証するうちにHLS形式の動画について詳しく知ることができたのでとても有意義でした。

### Kubernetes（AWS EKS）上で動作するプロダクトを運用する経験

上記の動画解析を伴うプロダクトでは並列でいくつかのバッチサービスと連携する必要がありました。
このようなサービスをAWS上に構築する場合、AWSにロックインしすぎること、開発者の開発環境で本番のAWS環境を再現するのが難しい点が問題になると考えています。
2年間ほどKubernetesを使ってサービスの運用をしてきましたが、こういったケースではKubernetesの導入がかなり効果的だと感じています。
AWS上でバッチを運用する場合、ECSタスクやAWS Batchなどいくつかの選択肢がありますが、Kubernetesを利用すればAWS EKS上のサービスとして稼働させることができます。
そしてKubernetesの環境はローカルで簡単に構築することが可能なので開発環境と本番環境で差異がほとんど現れません。また、別のクラウドベンダーに移行する際も難しくありません。
こういった開発者がインフラ環境を意識せずコードに集中できる仕組みを学べたのは大きな経験だったのかなと思います。
